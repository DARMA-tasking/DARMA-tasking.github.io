\doxysubsection{Tracing }
\hypertarget{trace}{}\label{trace}\index{Tracing@{Tracing}}
Trace distributed events.

The optional trace component {\ttfamily \doxylink{structvt_1_1trace_1_1_trace}{vt::\+trace::\+\+Trace}}, accessed via {\ttfamily vt::\+the\+Trace()} builds a distributed trace of events, including VT handlers, user events, and MPI invocations via the PMPI interface. It outputs \href{http://charm.cs.uiuc.edu/software}{\texttt{Projections}} log and sts files to enable performance analysis after execution.

To enable tracing at runtime, the trace component must be enabled at compile time with cmake. To enable tracing pass the cmake flag:\+ 
\begin{DoxyCode}{0}
\DoxyCodeLine{-\/Dvt\_trace\_enabled=1}

\end{DoxyCode}
\hypertarget{trace_tracing-spec-file}{}\doxysubsubsection{\texorpdfstring{Tracing Specification File}{Tracing Specification File}}\label{trace_tracing-spec-file}
In order to customize when tracing is enabled and disabled, a trace specification file can be passed to {\bfseries{{\itshape vt}}} via a command-\/line flag:\+ {\ttfamily -\/-\/vt\+\_\+trace\+\_\+spec -\/-\/vt\+\_\+trace\+\_\+spec\+\_\+file=filename.\+spec}.

For details about vt\textquotesingle{}s Specification File see \doxysectlink{spec-file}{Spec File}{0}\hypertarget{trace_incremental-tracing}{}\doxysubsubsection{\texorpdfstring{Incremental Trace Output}{Incremental Trace Output}}\label{trace_incremental-tracing}
The trace events can be configured to be saved to the file in the incremental matter. To configure the interval of the flushes use the {\ttfamily -\/-\/vt\+\_\+trace\+\_\+flush\+\_\+size=X} parameter. The {\ttfamily X} stands for the number of trace events before the next flush.

\begin{DoxyNote}{Note}
The incremental flushing will be blocked in the case of an incomplete user note. In that scenario there will be no output to the files. All trace events will be kept in memory and will be tried to be flushed on the next interval if the incomplete notes were closed. 
\end{DoxyNote}
